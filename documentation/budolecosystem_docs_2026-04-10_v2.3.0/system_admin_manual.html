System Admin Manual: Compliance Shield Operations

Version: 2.3.0 | Target Audience: DevOps, System Administrators

Overview

The Compliance Shield is an automated governance layer. As a System Admin, your role is to ensure the monitoring infrastructure is healthy and that thresholds align with current regulatory requirements (BSP Circular 808).

1. Monitoring the Compliance Board

Access the main dashboard. The Compliance Monitoring Board provides a real-time stream of security flags. Each flag is categorized by severity:

  • HIGH RISK (Red): Single transactions ≥ PHP 500,000 or Daily Aggregates ≥ PHP 1,000,000. These require immediate forensic review.
  • MEDIUM RISK (Amber): Velocity spikes (e.g., > 10 transfers in 1 hour). These may indicate automated scraping or money mule activity.

2. Configuration & Thresholds

IMPORTANT: Current thresholds are hardcoded in transaction-service/index.js for security integrity. Any changes to these values requires a deployment pipeline run and a new audit version.
Setting Value Regulatory Basis
High-Value Transaction (HVT) PHP 500,000.00 BSP AMLA Guidelines
Velocity Cap 5 Trans / Hour Cybersecurity Law (Fraud Prevention)
Daily Aggregate PHP 1,000,000.00 Institutional Risk Policy

3. Troubleshooting Alerts

If alerts are not appearing on the dashboard:

  1. Verify Redis/Pusher connection in the Realtime Settings page.
  2. Check transaction-service logs for [Compliance] Flag Triggered messages.
  3. Ensure the Admin is subscribed to the admin channel via the WebSocket provider.

4. Audit Trail Integrity

All compliance flags are immutable and stored in the AuditLog table. System Admins can verify the integrity of these logs by cross-referencing the entity: "Compliance" filter in the Security Audit page.
