Developer Manual: Institutional Compliance Shield

Version: 2.3.0 | Date: 2026-04-10

Technical Architecture

The Compliance Shield is a real-time monitoring layer integrated into the transaction-service and the admin dashboard. It satisfies BSP Circular 808 requirements for automated transaction monitoring and suspicious activity flagging.

1. AML Compliance Engine

Location: transaction-service/index.js

Implemented checkComplianceLimits, a centralized utility that evaluates transaction risk before final ledger entry. It broadcasts COMPLIANCE_ALERT events via the internal Gateway for real-time admin visualization.

}

2. Real-time Subscription (Frontend)

Location: apps/admin/components/ComplianceBoard.tsx

The Admin Dashboard uses the realtime utility to listen for COMPLIANCE_ALERT events. New flags are prepended to the board state instantly without requiring page refreshes.


useEffect(() => {
  const unsubscribe = realtime.on("COMPLIANCE_ALERT", (newAlert) => {
    setAlerts(prev => [newAlert, ...prev]);
  });
  return () => unsubscribe();
}, []);

3. API Compliance Filtering

Location: apps/admin/app/api/security/route.ts

Modified the security API to support a dedicated Compliance filter. This allows the Compliance Board to fetch historical flags while preserving institutional data privacy for general audit logs.

Phase 8: Software & Dependencies Discussion

The following technologies were selected for the Institutional Compliance Shield based on reliability, scalability, and adherence to regulatory standards:

Software/Library Rationale for Selection
Prisma ORM Chosen for its type-safe query building and automated migrations. In an AML context, the ability to generate schema-consistent audit logs is critical for forensic integrity.
Socket.io / Pusher Essential for real-time "Push" notifications. Traditional polling would create unacceptable latency in detecting high-risk transactions. These libraries provide reliable bi-directional communication.
Lucide-React Selected for its lightweight, consistent, and accessible icon set. High-severity risk iconography must be instantly recognizable for Admin operators.
Date-fns Used for precise timestamp manipulation during velocity and aggregate checks (e.g., calculating the 1-hour rolling window).

Compliance Standards

  • BSP Circular 808: Automated monitoring of transfers and cash operations.
  • PCI DSS v4.0: Secure audit logging and tamper-proof trail for financial actions.
  • NPC DPA 2012: Ensuring PII in audit metadata is restricted to authorized Compliance Officers.
