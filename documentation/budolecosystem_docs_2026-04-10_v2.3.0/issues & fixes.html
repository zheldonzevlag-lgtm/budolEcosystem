Issues & Fixes: v2.3.0 Release

Implementation Log

The following issues were identified and resolved during the integration of the Institutional Compliance Shield.

ISSUE-230-01: Prisma Validation Failure in Compliance Tests

Description: Automated compliance monitoring tests failed during upsert operations because mandatory fields passwordHash and phoneNumber were missing from the test user creation payload.

FIX: Schema-Compliant Test Seeding

Modified scripts/test_scripts/compliance_monitor.test.js to include realistic dummy values for all required schema fields, ensuring the test suite executes in a sanitized institutional environment. Verified passing status on 2026-04-10.

ISSUE-230-02: Real-time UI State Desynchronization

Description: Dashboard pages were only revealing historical flags on full refresh, causing a "Blind Spot" for real-time institutional monitoring during the 10-minute caching window.

FIX: Event-Driven State Prepend

Implemented a useEffect listener in ComplianceBoard.tsx that subscribes to the COMPLIANCE_ALERT event. New alerts are now prepended to the top of the list in real-time, bypassing server-side cache for instant visual oversight.

ISSUE-230-03: Security Filter Broadness

Description: The /api/security endpoint was returning too much metadata for general staff, potentially exposing internal compliance flag forensic data to non-authorized roles.

FIX: Explicit Compliance Scoping

Extended app/api/security/route.ts with a dedicated Compliance filter case. This ensures that sensitive AML-related audit logs are only scoped and returned when requested by the specific monitoring board, facilitating RBAC-lite privacy enforcement.

Version 2.3.0 System Stability: VERIFIED
