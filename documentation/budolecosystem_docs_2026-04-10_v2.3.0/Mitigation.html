Mitigation Strategies: v2.3.0 Compliance Shield

Version: 2.3.0 | Compliance: Institutional / Regulatory

Overview

Direct responses to the risks identified in the Risk Register. These mitigations combine automated logic with institutional protocol.

M-001: Threshold Evasion Countermeasures

Risk: Users splitting transactions (Smurfing).

Mitigation: Implementation of Daily Aggregate Monitoring in the transaction-service. Even if a user splits a 1.2M PHP transfer into three 400k transactions, the system flags the third event as a breach of the 1M PHP daily threshold.

M-002: Real-time Alert Resiliency

Risk: Failure of WebSocket notifications.

Mitigation: Dual-track synchronization. The ComplianceBoard.tsx performs an initial REST fetch from the /api/security endpoint on mount to ensure historical flags are captured even if the WebSocket stream dropped during the user's absence.

M-003: Administrative Privacy (NPC Compliance)

Risk: Unauthorized staff viewing forensic transaction data.

Mitigation: Enforcement of Entity-Level Scoping in the Audit API. Forensic compliance logs are only returned when the filter=Compliance parameter is passed, which is restricted to the Compliance Monitoring Board available only to authorized admin roles.

M-04: Fraud Velocity Throttling

Risk: Automated system exploitation via high-frequency transfers.

Mitigation: Static Velocity Checks (5 events/hour). This provides an early warning system for accounts that may have been compromised by bots or are being used for rapid funds dispersion.
