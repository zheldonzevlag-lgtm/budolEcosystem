Developer Manual: Tiered Limits & Volume Tracking

Technical Overview

The system now utilizes a getMonthlyCumulativeVolume helper to track transaction flow on a per-user, per-month basis. This allows for fine-grained control over "Basic" tiers without hard-blocking features.

Key Implementation Details

1. Monthly Volume Calculation

Calculates the sum of COMPLETED transactions from the 1st of the current month to the current timestamp.

const getMonthlyCumulativeVolume = async (userId, type) => {
    const startOfMonth = new Date();
    startOfMonth.setDate(1);
    startOfMonth.setHours(0, 0, 0, 0);

    const filter = type === 'OUTBOUND' ? { senderId: userId } : { receiverId: userId };
    const agg = await prisma.transaction.aggregate({
        where: { ...filter, status: 'COMPLETED', createdAt: { gte: startOfMonth } },
        _sum: { amount: true }
    });
    return parseFloat(agg._sum.amount || 0);
};

Logic Flow Changes

P2P Transfer (/transfer)

Previously, BASIC accounts were blocked via simple equality check. Now, they are permitted if their month-to-date (MTD) outbound volume + current amount is ≤ 5,000.

Cash-In (/cash-in)

Enforces two distinct checks for BASIC users:

  • Static Ceiling: Total balance cannot exceed ₱10,000.
  • Dynamic Flow: Cumulative monthly inbound cannot exceed ₱5,000.

Dependencies

  • Prisma ORM: Used for efficient aggregation queries.
  • CommonJS: Backend service utilizes CJS for compatibility with legacy monitoring hooks.
