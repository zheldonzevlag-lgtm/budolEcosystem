Developer Manual (v2.4.8)

Technical Overview

Version v2.4.8 focuses on resolving high-priority stability issues in the Flutter Mobile application and data integrity in the Forensic Audit Trail.

1. Mobile Stability: The 'toDouble' Utility

Problem: Backend JSON responses for numeric fields (like wallet balances) sometimes return as String types. Direct calls to .toDouble() in Dart result in a crash.

Solution: Implemented a robust AmountUtils.toDouble() helper that handles num, String, and null values safely.

static double toDouble(dynamic value) { if (value == null) return 0.0; if (value is double) return value; if (value is int) return value.toDouble(); if (value is String) { if (value.isEmpty) return 0.0; final clean = value.replaceAll(',', ''); return double.tryParse(clean) ?? 0.0; } return 0.0; }

Code References:

  • lib/utils/formatters.dart - Utility Implementation
  • lib/screens/cash_in_screen.dart - Limit Check logic
  • lib/services/api_service.dart - Balance parsing

2. Admin Login: MathCaptcha Hydration

Problem: React hydration errors due to Math.random() calling during render, causing SSR/Client mismatch.

Solution: Deployed captcha generation inside a useEffect hook, ensuring it only runs on the client. Replaced 0-init with null to handle placeholder states.

Code References:

  • apps/admin/components/MathCaptcha.tsx

3. Backend: Forensic Audit Trail Unification

Problem: Duplicate P2P_TRANSFER_COMPLETED logs due to redundant calls in the transfer handler.

Solution: Removed manual prisma.auditLog.create and consolidated all logging into the shared createAuditLog helper.

Code References:

  • services/transaction-service/index.js
Compliance Check: All logging changes adhere to BSP Circular 808 standards for non-repudiation and accurate event sequencing.
