🐞 Issues & Fixes — v1.3.93

April 17, 2026 | Branch: release/1.3.93

Critical Bugs Resolved

#SeverityComponentDescriptionRoot CauseFix Applied
BUG-001 CRITICAL MapPicker (Widget) Searching "calamba laguna" returned "Address not found" snackbar. Map pin did not move. Address input was not populated. Flutter's geocoding package (locationFromAddress) depends on Android/iOS native Google Play Services geocoding hooks. These are absent in Flutter Web builds, causing all forward geocoding calls to throw unhandled exceptions. Implemented try/catch around native locationFromAddress(). On failure, code falls back to https://nominatim.openstreetmap.org/search REST endpoint. On success, updates _selectedLocation state and calls _mapController.move() to reposition the map.
BUG-002 CRITICAL MapPicker (Widget) Tapping/pinning a location on the map did not auto-fill the search bar with an address string. The original banner was a static Text widget ("Tap on the map to pin your exact location") — no geocoding call was connected to the onTap event on FlutterMap. Added _reverseGeocodeCoordinate(latLng) call inside the TileLayer.onTap handler and inside _getCurrentLocation(). Also uses Nominatim /reverse as fallback.
BUG-003 WARNING map_picker.dart flutter analyze reported two unnecessary_non_null_assertion warnings causing Exit Code 1. Inside a resultLatLng != null block, resultLatLng! was used, which is redundant. The setState closure prevents Dart's null promotion from spreading inside closures automatically. Extracted final loc = resultLatLng; and used loc inside the closure, removing the ! operators. Resolved in two passes.
BUG-004 WARNING KYCVerificationScreen After confirming a pin from the map, if native geocoding failed, the address field in KYC form remained empty. _pinAddress() only used placemarkFromCoordinates() with no fallback. On Web/emulator, this throws and the address field is never populated. Wrapped native call in try/catch. Added identical Nominatim /reverse fallback. Address field now reliably populates on all platforms.
BUG-005 TEST FAIL test/version_test.dart flutter test exited with code 1: "Expected '1.3.83', Actual '1.3.93'". The version assertion in the unit test was never updated from the baseline version. Updated both the test name string and the expect() assertion to expect '1.3.93'.
