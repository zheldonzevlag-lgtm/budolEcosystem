Risk Register: Phone Normalization

RiskImpactMitigation
Format Collision Low. Since phoneNumber is unique across all formats, searching for variants won't return multiple users in a correctly constrained DB. Database-level uniqueness constraints.
Foreign Numbers Current logic is PH-centric (+63). International growth will break simple length-based normalization. Phase 8 Roadmap item for libphonenumber integration.

Future Recommendations: Data Unification

  • Unified Storage: Implement a migration script to convert all existing phoneNumber records to E.164 format (+63...) to eliminate runtime normalization overhead.
  • Input Validation: Update the registration & profile UI to enforce international formatting at the source.
  • SMS Gateway Sync: Ensure the normalization logic matches the input requirements of the BudolPay SMS gateway provider to reduce delivery failures.
