Developer Manual: Phone Normalization Engine

Rationale

User registration in BudolPay allows for varying phone number inputs (e.g., 09xx, +63xx). During P2P transfers, if the sender enters a format different from the receiver's registration record, the lookup fails. v2.4.2 implements a Multi-Variant Search Pattern to eliminate this friction.

Core Implementation

Location: transaction-service/index.js


const getPhoneVariants = (input) => {
    const clean = input.replace(/\D/g, '');
    if (clean.length === 10) { // e.g., 9484099400
        return [`0${clean}`, `+63${clean}`];
    }
    if (clean.length === 11 && clean.startsWith('0')) {
        return [clean, `+63${clean.slice(1)}`];
    }
    // ... handles 63 and other variants
};

Database Integration

The lookup utilizes the Prisma in operator within an OR block to search for all potential matches in a single query, maintaining high performance.


const recipientUser = await prisma.user.findFirst({
    where: {
        OR: [
            { email: recipient },
            { phoneNumber: { in: variants } }
        ]
    }
});
