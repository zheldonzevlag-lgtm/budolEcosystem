Developer Manual v2.2.7

Technical Strategy: Actor Attribution

To ensure individual accountability (PCI-DSS 10.2.1), we migrated from "system-only" logging to "actor-explicit" logging for all administrative routes. This relies on the actorName and actorEmail fields in the createAuditLog utility.

1. Admin Attribute Capture (API Proxy)

Every administrative POST/PUT now decodes the adminId from the body and executes a lookup in the User table to retrieve forensic markers.

Open Employee API
// Extracting actor identity for provisioning const actor = await prisma.user.findUnique({ where: { id: adminId }, select: { id: true, firstName: true, lastName: true, email: true } }); await createAuditLog({ action: "ACCOUNT_PROVISIONED", userId: actor.id, actorName: `${actor.firstName} ${actor.lastName}`, actorEmail: actor.email, // ... });

Impacted Systems

  • Admin Dashboard: Modified to send adminId in all provisioning modals.
  • Security Gateway: Now links automated scans to the initiating compliance officer.
  • User Management: KYC overrides and document rotations now possess a clear audit trail.

Maker-Checker Compliance

The v2.2.7 implementation enforces Segregation of Duties (SoD) by ensuring the adminId of the Maker is strictly captured during CHANGE_REQUEST_CREATED, independent of the local session storage.
