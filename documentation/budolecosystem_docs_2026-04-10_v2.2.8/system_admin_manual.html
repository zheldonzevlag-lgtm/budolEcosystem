🚀 Deployment Checklist for v2.2.8

⚠️ CRITICAL (Pre-deploy): Ensure PAYMENT_GATEWAY_URL is set in the budolshap Vercel project environment variables before merging. Without it, the cancel proxy falls back to localhost:8004 and all cancel calls will silently fail in production.
#StepServiceAction
1 Set PAYMENT_GATEWAY_URL env var budolshap (Vercel) Go to Vercel → budolshap project → Settings → Environment Variables → Add PAYMENT_GATEWAY_URL = https://payment-gateway-service-two.vercel.app
2 Merge release/v2.2.8 → main All Create PR, get review, merge. Vercel auto-deploys on merge.
3 Monitor payment-gateway-service logs payment-gateway-service Watch for [Gateway] ✅ Transaction XXX CANCELLED logs after first user cancellation
4 Verify Admin Dashboard Transaction status budolpay Admin Cancel a test QR payment and confirm the Admin Dashboard shows CANCELLED, not PENDING

📋 Monitoring – What to Watch

  • Gateway logs: Look for [Gateway] ✅ Transaction XXX CANCELLED on every user cancellation
  • Gateway logs: Any [Gateway] Cancel: Transaction not found warrants investigation if frequent
  • Admin Dashboard: Spot-check that cancelled orders show CANCELLED (not PENDING) in Global Transactions
  • Risk R-003: If gateway is unreachable, PENDING transactions will accumulate. Monitor pending count > 30 min old and alert ops.

🔄 Rollback Plan

The changes are additive — a new endpoint and a new API route. Rolling back means reverting the release/v2.2.8 merge. Transactions that were correctly CANCELLED before rollback will remain CANCELLED. No data migration required.

ℹ️ The dual-lookup in the gateway cancel endpoint (by referenceId then by UUID) is backward-compatible and does not change any existing endpoint behaviour.
