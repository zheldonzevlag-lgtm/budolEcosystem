Purpose & Background

v2.2.8 closes the gap between the Order cancellation path in budolshap and the Transaction lifecycle inside the budolPay payment-gateway-service. Prior to this release, clicking "Cancel Payment" or letting the checkout timer expire correctly cancelled the Order record but left the Transaction record in a PENDING state forever.

1. New Endpoint: POST /cancel/:referenceId

File: payment-gateway-service/api/index.js

Request

POST https://<GATEWAY_BASE_URL>/cancel/:referenceId
Content-Type: application/json

{
  "reason": "User cancelled payment from cart"  // optional
}

Response – Success (200)

{
  "success": true,
  "status": "CANCELLED"
}

Response – Already Cancelled (200 idempotent)

{
  "success": true,
  "status": "CANCELLED",
  "message": "Already cancelled"
}

Response – COMPLETED guard (409)

{
  "error": "Cannot cancel a completed transaction"
}

Business Logic

StepWhatWhy
1Lookup transaction by referenceIdIdentify the correct ledger record
2Guard: reject if COMPLETEDPCI DSS – do not reverse settled transactions
3Guard: idempotent if already CANCELLEDPrevent duplicate updates from retries
4UPDATE status to CANCELLEDAccurate ledger per BSP Circular 808
5Write audit log via createCentralizedAuditLogPCI DSS 10.2.4 compliance
6Notify Admin via notifyAdmin()Real-time Admin Dashboard update
7Notify User via notifyUser() if senderId knownLive transaction status on mobile app

2. Checkout Page HTML – Timer & Close Button Fix

File: payment-gateway-service/api/index.js (inline HTML template)

cancelTransaction() Helper (new)

async function cancelTransaction(reason) {
  await fetch('/cancel/' + referenceId, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ reason })
  });
}

Close Button (before → after)

// BEFORE: No action – user navigated away, transaction stayed PENDING
<button class="close-btn">×</button>

// AFTER: Cancel transaction THEN navigate
document.querySelector('.close-btn').addEventListener('click', async () => {
  clearInterval(timerInterval);
  clearInterval(pollInterval);
  await cancelTransaction('User closed checkout page');
  window.location.href = cancelUri || '/cart';
});

Timer Expiry (before → after)

// BEFORE: reload (transaction stays PENDING)
window.location.reload();

// AFTER: cancel transaction THEN navigate
cancelTransaction('Payment session expired').then(() => {
  window.location.href = cancelUri || '/cart';
});

3. New Proxy Route: /api/payment/cancel

File: budolshap/app/api/payment/cancel/route.js NEW

Request (from OrderSummary.jsx)

POST /api/payment/cancel
Content-Type: application/json

{
  "referenceId": "JON-20260410120000-AB12CD34",  // gateway referenceId (preferred)
  "intentId": "uuid-xxxx",                         // gateway Transaction.id (fallback)
  "reason": "User cancelled payment from cart"
}

This route reads PAYMENT_GATEWAY_URL (or falls back to localhost:8004) and forwards the request to POST /cancel/:referenceId on the gateway. An AbortSignal.timeout(8000) prevents hanging the user's browser on a slow gateway response.

4. OrderSummary.jsx – handleQRCancel Update

File: budolshap/components/OrderSummary.jsx

Two-step Cancellation Flow

const handleQRCancel = async (orderId) => {
  const token = getToken();

  // STEP 1: Cancel Order in budolshap DB
  await fetch(`/api/orders/${orderId}/cancel`, { method: 'POST', ... });

  // STEP 2: Cancel Transaction in budolPay gateway DB
  const gatewayRef = qrData?.referenceId || qrData?.paymentIntentId;
  await fetch('/api/payment/cancel', {
    method: 'POST',
    body: JSON.stringify({
      referenceId: qrData?.referenceId,
      intentId: qrData?.paymentIntentId,
      reason: 'User cancelled payment from cart'
    })
  });

  setQrData(null);
  toast.success('Payment cancelled. Your cart items are still saved.');
};

qrData State – Added referenceId

// BEFORE
const qrData = {
  qrCode: normalizedQrCode,
  paymentIntentId,
  paymentMethod,
  orderId,
  amount
};

// AFTER – referenceId added for gateway cancel calls
const qrData = {
  qrCode: normalizedQrCode,
  paymentIntentId,
  referenceId: paymentData.referenceId || paymentData.reference || null,  // NEW
  paymentMethod,
  orderId,
  amount
};
