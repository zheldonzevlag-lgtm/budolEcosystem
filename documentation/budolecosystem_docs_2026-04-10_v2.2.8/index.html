🐛 Problem Statement

When a user selected a QR-based payment method (budolPay, Maya, GrabPay, QRPh) and then cancelled by clicking the X button, Cancel Payment link, or letting the 10-minute timer expire, the following happened:

  • ✅ Order record (budolshap DB) → correctly set to CANCELLED
  • ❌ Transaction record (budolPay gateway DB) → remained PENDING indefinitely

This caused stale PENDING transactions to appear in the Admin Dashboard, skew financial reconciliation reports, and violate BSP Circular No. 808 accurate ledger requirements.

🔄 Cancellation Flow (After Fix)

1
User clicks Cancel Payment or X in QRCodeModal (budolshap frontend)
2
handleQRCancel(orderId) is called in OrderSummary.jsx
3
Step A: POST /api/orders/{orderId}/cancel → Order record set to CANCELLED in budolshap DB
4
Step B: POST /api/payment/cancel with referenceId → proxied to gateway's POST /cancel/:referenceId
5
Gateway: Transaction status updated to CANCELLED, audit log written, Admin notified via Realtime
6
QR Modal dismissed, user sees toast: "Payment cancelled. Your cart items are still saved."
