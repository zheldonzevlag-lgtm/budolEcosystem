Issue #001 – Cancelled Payments Leave Gateway Transaction in PENDING State

FieldDetails
Status✅ FIXED
SeverityHigh – Financial data integrity
Discovered2026-04-10 – Admin Dashboard showed PENDING transactions for orders that were clearly cancelled by the user
Root Cause The cancellation flow in OrderSummary.jsx only called POST /api/orders/{id}/cancel (budolshap's own DB). The Transaction table in the budolPay payment-gateway database has no foreign-key link to the Order table — it is a separate bounded context with its own lifecycle. No code path existed to update the gateway's Transaction status on user-initiated cancellations.
Impact
  • Admin Dashboard "Global Transactions" table: cancelled orders showed PENDING payment
  • Financial reconciliation CSV exports contained inaccurate PENDING records
  • BSP Circular 808 ledger accuracy requirement violated
  • Checkout page "X" button and 10-min timer also did not cancel the gateway transaction
Fix Applied
  1. Added POST /cancel/:referenceId endpoint to payment-gateway-service
  2. Checkout HTML page's close button and timer-expiry now call /cancel/:referenceId before redirecting
  3. Created budolshap/app/api/payment/cancel/route.js proxy route
  4. Updated handleQRCancel in OrderSummary.jsx to also call the proxy
  5. Added referenceId to the qrData state object for cancel call availability
