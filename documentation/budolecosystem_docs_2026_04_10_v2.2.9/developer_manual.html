Developer Manual

Version: 2.2.9 | Date: 2026-04-10

Purpose & Rationale

The BudolPay Mobile App authenticates via the Auth Service, expecting OTP verification at /login/mobile/verify-otp. However, the backend only supported /verify-otp, causing 404 HTML fallback responses on mobile. Furthermore, system logout functionality and forensic logs used the `email` directly rather than presenting the `firstName` + `lastName` for Staff Identity validation. This patch synchronizes endpoints and expands audit metadata to fulfill UX error handling (via toast notifications) and audit trace denormalization.

Technical Explanation & Code Details

1. Mobile Auth Endpoint Binding

Location: auth-service/index.js

We attached an array of paths to the express POST handler. This aligns the BudolPay Mobile App's expectation without breaking the web expectation.


// Verify OTP (Universal Endpoint for Mobile & Web)
app.post(['/verify-otp', '/login/mobile/verify-otp'], async (req, res) => { ... }

2. Forensic Audit Identity Logging

Location: apps/admin/app/security/page.tsx and apps/admin/lib/audit.ts

Prior to this version, if the User foreign key lookup failed (common with mobile cross-app boundaries), the audit log silently omitted the user's name. We modified the table column from Actor to Staff Identity and implemented a fallback that consumes denormalized metadata.actorName.


{log.metadata?.actorName || (log.user ? `${log.user.firstName || ''} ${log.user.lastName || ''}`.trim() || log.user.name || log.user.email : 'System')}

3. UX Enhancement: Non-Destructive Credentials

Location: apps/admin/app/login/page.tsx

Implemented `react-hot-toast` for `top-center` notifications, allowing standard error messages over clearing the component's state variables (formData.email/password), enabling the user to immediately retry without re-typing their password.

Dependencies

  • react-hot-toast in Admin App
  • Prisma ORM for database schemas
