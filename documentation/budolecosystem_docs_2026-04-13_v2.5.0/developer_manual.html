Developer Manual - v2.5.0

1. Adaptive Greeting Logic

File: home_screen.dart

Implemented a conditional renderer that swaps between Column (Vertical) and Row (Classic) layouts based on user preference.

/// WHY: Adaptive UI allows users to prioritize visibility or density.
Widget _buildAdaptiveGreeting(BuildContext context, ApiService api, String name) {
  final isVertical = api.greetingLayout == 'vertical';
  
  if (isVertical) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        Text('Good Morning,', style: TextStyle(color: Colors.white70)),
        Text(name, style: TextStyle(fontSize: 24, fontWeight: FontWeight.bold)),
      ],
    );
  } else {
    return Row(
      children: [
        Text('Hi, ' + name, style: TextStyle(fontWeight: FontWeight.bold)),
      ],
    );
  }
}

2. Profile Completeness Algorithm

File: api_service.dart

Calculates completion weight based on verified data points. Weights: Name (25%), Email (25%), PIN (25%), KYC (25%).

double get profileCompletion {
  double progress = 0.0;
  if (user['firstName'] != null) progress += 0.25;
  if (user['email'] != null) progress += 0.25;
  if (user['pinHash'] != null) progress += 0.25;
  if (user['kycStatus'] == 'VERIFIED') progress += 0.25;
  return progress;
}

4. Dependency & Software Rationale (Phase 8)

The following core dependencies were selected for the v2.5.0 Adaptive UI release to balance performance, security, and developer experience:

Dependency Rationale
provider Optimized for high-frequency UI updates (e.g.,MPIN masking) with minimal rebuilding overhead.
mobile_scanner Selected for robust QR 2.0 support and haptic feedback integration, essential for retail point-of-sale efficiency.
tflite_flutter Enables on-device FaceNet biometric verification, ensuring PCI DSS compliance by avoiding PII transmission to cloud servers.
shared_preferences Used for lightweight UI state persistence (Greeting Layout, Theme preference) without requiring SQL overhead.
