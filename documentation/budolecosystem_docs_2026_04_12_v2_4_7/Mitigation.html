Mitigation Plan: v2.4.7

Version: v2.4.7 Date: 2026-04-13

Purpose

This document describes the specific mitigations applied for each risk identified in the v2.4.7 Risk Register, including failover strategies and monitoring approaches.

Mitigation Details

RSK-001: DRS Heartbeat Failure

Mitigation: The heartbeat uses setInterval(...).unref() so it does not block process shutdown. The Admin Dashboard DRS shield displays a warning if the last ping is older than 2 minutes, prompting admin action.

Failover: On detection of stale heartbeat, alert is displayed on the Compliance Board. Admins restart the transaction-service via npm start or the service manager.

Monitoring: Query SystemSetting where key = 'drs_heartbeat_last_ping' and alert if updatedAt < NOW() - INTERVAL '2 minutes'.

RSK-002: Payment Gateway Offline During Testing

Mitigation: payment-security.test.js now includes a beforeAll health-check. All 4 integration tests skip gracefully with it.skip() when the gateway is unreachable.

Failover: CI pipeline should run npm start before running the test suite. Docker Compose setup is recommended for v2.4.8.

RSK-003: IPv6/IPv4 Localhost Resolution

Mitigation: All test files now use 127.0.0.1 explicitly instead of localhost. This is documented as a mandatory standard in the Developer Manual test patterns table.

Prevention: Code review checklist updated: any new test using localhost must be flagged and replaced with 127.0.0.1.

RSK-005: Cross-Platform Build Failures

Mitigation: Removed Unix-specific prebuild script (mkdir /tmp/prisma_cache) from apps/admin/package.json. Prisma generate now runs via standard Vercel build hooks.

Prevention: All CI builds run on both Windows and Linux runners to catch cross-platform issues early.

RSK-006: AI Anti-Spam False Positives

Mitigation: EWMA spam score thresholds are configurable via environment variables. Default threshold is 0.6 (60% confidence). Legitimate users with unusual email patterns may contact support for manual review.

Next Steps: Implement an admin override endpoint to whitelist specific registration patterns. See Future Recommendations.

RSK-008: OTP Timing Attack

Mitigation: Rate limiting is enforced on the OTP verify endpoint (5 attempts / 15 minutes). JWT pre-auth tokens expire in 5 minutes.

Monitoring: Failed OTP attempts are logged to the centralized AuditLog with IP address for forensic review.
