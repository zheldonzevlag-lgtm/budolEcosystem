Developer Manual: v2.4.7 Architecture

Component: Backend/Admin UI Version: 2.4.7

1. DRS Engine Telemetry (Heartbeat)

To provide real-time status in the Admin Dashboard without manual refresh polling, a heartbeat mechanism was injected into the transaction-service.

Implementation Details

File Reference: transaction-service/index.js

function startDrsHeartbeat() {
    setInterval(async () => {
        try {
            await prisma.systemSetting.upsert({
                where: { key: 'DRS_ENGINE_HEARTBEAT' },
                update: { value: new Date().toISOString() },
                create: { key: 'DRS_ENGINE_HEARTBEAT', value: new Date().toISOString() }
            });
        } catch (e) { /* silent fail to prevent crash */ }
    }, 30000).unref();
}

Rationale: The .unref() call is critical. It allows the Node.js event loop to exit even if the interval is active, which prevents Jest test suites from hanging indefinitely.

2. Admin Dashboard UI Logic

The dashboard now dynamically calculates system health based on the telemetry timestamp.

Health Thresholds

  • ACTIVE: Last heartbeat < 2 minutes ago.
  • DELAYED: Last heartbeat 2-5 minutes ago.
  • OFFLINE: Last heartbeat > 5 minutes ago.
