New Files Introduced in v2.4.7

📄 payment-gateway-service/api/utils.js [Open File]

Purpose: Extracted pure utility functions from api/index.js to make them testable without importing the Express server's side-effects (DB startup, app.listen).

Why this exists: When Jest imported api/index.js directly to test generateSecureReferenceId, it triggered the startup IIFE that connected to the database and started a server, leaving open handles that prevented Jest from exiting cleanly.

// api/utils.js — Side-effect-free utility module
const crypto = require('crypto');

// WHY: Extracted from api/index.js for testability.
// Tests can safely import this without triggering DB or server startup.
function generateSecureReferenceId() {
  const timestamp = getLegacyManilaISO()
    .replace(/[-T:.Z]/g, '')
    .slice(0, 14);
  const randomBytes = crypto.randomBytes(4).toString('hex').toUpperCase();
  return `JON-${timestamp}-${randomBytes}`;
}

module.exports = { getLegacyManilaISO, getLegacyManilaDate, generateSecureReferenceId };

Key Code Changes

1. body-parser Charset Fix — [payment-gateway-service/api/index.js]

Change: Updated bodyParser.json() to use a custom type() function.

Rationale: Clients (including PowerShell's Invoke-RestMethod) append charset=UTF-8 to their Content-Type headers. The default body-parser rejected this with HTTP 415.

// BEFORE (strict — rejects 'application/json; charset=UTF-8')
router.use(bodyParser.json());

// AFTER (permissive — accepts any application/json variant)
router.use(bodyParser.json({
  type: (req) => req.headers['content-type']?.startsWith('application/json')
}));

2. Startup Diagnostic Guard — [payment-gateway-service/api/index.js]

Change: Wrapped the DB startup IIFE in if (process.env.NODE_ENV !== 'test').

Why: Even after extracting utils.js, if index.js is imported by any test, the diagnostic block would attempt a DB connection. The guard prevents this entirely in test environments.

// WHY: Skip DB diagnostics in Jest (NODE_ENV=test) to prevent open handles
if (process.env.NODE_ENV !== 'test') {
  (async () => {
    const count = await prisma.user.count();
    console.log(`✅ DB connected. ${count} users.`);
  })();
}

3. Service Availability Guard in Tests

Pattern: Integration tests that require live services now use a beforeAll health-check to skip gracefully when the service is offline.

let gatewayAvailable = false;

beforeAll(async () => {
  try {
    const res = await axios.get(`${GATEWAY_URL}/health`, { timeout: 2000, validateStatus: () => true });
    gatewayAvailable = res.status === 200;
  } catch { gatewayAvailable = false; }
});

// Conditionally skip when service is offline
const itIfGateway = (...args) => gatewayAvailable ? it(...args) : it.skip(...args);

Files using this pattern: payment-security.test.js

4. Admin Package.json Cleanup — [apps/admin/package.json]

Change: Removed the legacy prebuild script that ran mkdir /tmp/prisma_cache.

Why: This Unix-only command caused Vercel and Windows CI builds to fail. Standard Prisma generate logic is sufficient.
