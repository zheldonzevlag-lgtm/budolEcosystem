Future Recommendations: Consolidated Roadmap

Last Updated: v2.4.7 (2026-04-13) Next Milestone: v2.4.8

Short Term (v2.4.8 — Next Sprint)

🔧 FRec-001: Docker Compose Integration Test Environment

Rationale: The payment-security.test.js suite requires a live payment gateway. Currently it skips in offline environments, meaning it never runs in CI. A Docker Compose setup would start all services before Jest runs.

Implementation: Create budolpay-0.1.0/docker-compose.test.yml with all 5 microservices. Add a test:e2e npm script that runs docker-compose up -d then Jest.

Compliance: PCI DSS Req 11.3 (Penetration Testing), BSP MORB Sec. 114

🔧 FRec-002: PayMongo / Xendit Live Sandbox Integration

Rationale: The payment-gateway-service already has provider routing logic for PayMongo and Xendit, but uses placeholder checkout URLs. The gateway needs real API keys for end-to-end payment testing.

Implementation: Add PAYMONGO_SECRET_KEY and XENDIT_SECRET_KEY environment variables. Update /create-intent to call the real provider APIs in production.

Compliance: BSP Circ. No. 1033 (E-Money Issuance), PCI DSS Req 4.2 (Encrypted Transmission)

🔧 FRec-003: Prometheus / Grafana Health Monitoring

Rationale: The DRS Heartbeat writes to PostgreSQL, but there is no active alerting if the heartbeat stops. Prometheus + Grafana would enable real-time dashboards and PagerDuty integration.

Implementation: Expose a /metrics endpoint on each service returning Prometheus-compatible counters. Deploy Grafana on the same VPS.

🔧 FRec-004: KYC Address Reverse-Geocoding (Mobile)

Rationale: The BudolPay mobile app displays raw GPS coordinates for pinned KYC locations. Users need human-readable addresses. The geocoding and connectivity_plus packages have been identified as the correct solution (see conversation 0d82d865).

Implementation: Integrate geocoding Flutter package. Add connectivity check to prevent pinning without network access. Show full address string below the map pin.

Medium Term (v2.5.0)

🔮 FRec-005: AI Anti-Spam Admin Override Endpoint

Rationale: Legitimate users with unusual email patterns (e.g., academic or government addresses) may be incorrectly blocked by the EWMA spam engine. Admins need a whitelist management interface.

Implementation: Add POST /admin/spam-whitelist endpoint requiring GENERAL_MANAGER role. Store whitelisted email patterns in SystemSetting table.

🔮 FRec-006: BIR e-Receipts Integration

Rationale: BSP and BIR require fintech platforms to issue official electronic receipts for all transactions. budolShap transactions currently lack BIR-compliant receipt numbers.

Implementation: Integrate with BIR's eSales/eSERV API to generate official receipt numbers for each completed MERCHANT_PAYMENT transaction.

Compliance: BIR RR 8-2022 (Electronic Official Receipts)

🔮 FRec-007: BlitzXpress Foundation Completion

Rationale: The BlitzXpress platform was initialized (conversation cf043dc8) but not completed. The Next.js web app, Express backend, and Flutter driver need to be wired together.

Implementation: Continue from the BlitzXpress implementation plan. Priority: Express backend routes, then Next.js dashboard, then Flutter integration.
