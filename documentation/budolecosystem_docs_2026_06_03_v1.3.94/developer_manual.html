Developer Manual – v1.3.94

Prisma Schema Sync & Vercel Production DB Fix

← Index Tasks Test Results Issues & Fixes

Purpose

This release resolves Vercel runtime crashes on the admin dashboard caused by a Prisma Client schema mismatch between the admin app's local schema and the actual production Neon database structure.

Rationale

The admin app (apps/admin) maintained its own prisma/schema.prisma file that was outdated and contained e-commerce models (Product, Store, Category) not present in the production database. The generated Prisma Client expected columns like points and expireAt instead of the actual hits and expiresAt columns, causing runtime query failures.

Technical Explanation

Root Cause

  1. Schema Mismatch: apps/admin/prisma/schema.prisma defined model SystemSettings (plural) and RateLimit with fields points/expireAt. The production database uses SystemSetting (singular) with hits/expiresAt.
  2. Status Route Bug: /api/system/status queried prisma.systemSettings.findUnique({where: {id: 'default'}}) — table doesn't exist.
  3. Wrong DB Cluster: push_env.cjs pointed to ep-bitter-wildflower-a1y0z1id-pooler instead of active cluster ep-wandering-breeze-aoin4z9c-pooler.

Code Changes

1. Schema Sync – apps/admin/prisma/schema.prisma

Overwritten with the source-of-truth from packages/database/prisma/schema.prisma. Key models:

// Correct singular model name matching production DB table
model SystemSetting {
  id          String   @id @default(uuid())
  key         String   @unique
  value       String
  isSecret    Boolean  @default(false)
  description String?
  updatedAt   DateTime @updatedAt
  appId       String?
  createdAt   DateTime @default(now())
  group       String?
  isActive    Boolean  @default(true)
}

// Uses 'hits' and 'expiresAt' (not 'points'/'expireAt')
model RateLimit {
  id        String   @id @default(uuid())
  key       String   @unique
  hits      Int      @default(1)
  expiresAt DateTime
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

2. Status API Route – apps/admin/app/api/system/status/route.ts

Changed from prisma.systemSettings.findUnique({where:{id:'default'}}) to:

// Query singular SystemSetting model for DRS heartbeat timestamp
heartbeatSetting = await prisma.systemSetting.findUnique({
    where: { key: 'DRS_ENGINE_HEARTBEAT' }
});

3. Environment Variables – apps/admin/push_env.cjs

// BEFORE (incorrect cluster)
"DATABASE_URL": "...ep-bitter-wildflower-a1y0z1id-pooler..."

// AFTER (correct production cluster)
"DATABASE_URL": "...ep-wandering-breeze-aoin4z9c-pooler.c-2..."
