Overview & Architecture

budolEcosystem is a Philippine fintech e-commerce platform deployed across 5 Vercel projects spanning 10+ serverless endpoints. All projects are region-pinned to sin1 (Singapore) for lowest latency to the Philippines.

Architecture Diagram

budolshap→Cloudinary / Pusher / PayMongo / Sentry
budolpay Admin→Cloudinary / Pusher / Sentry
budolpay API GW→RDS PostgreSQL (budolpay)
budolID→RDS PostgreSQL (budolid)
budolAccounting→RDS PostgreSQL (budolaccounting)
WebSocket Server←Render (standalone, not Vercel)
Note: The WebSocket server uses Socket.io and requires persistent connections — deployed on Render, not Vercel.

⚠ Important: Monorepo Structure

The 7 budolpay microservices share a monorepo at budolpay-0.1.0/ with npm workspaces. Each service is deployed as an independent serverless function, but they share packages (@budolpay/database, @budolpay/audit, etc.).

Vercel will install dependencies from the root package.json workspaces. Ensure rootDirectory is set to budolpay-0.1.0 in the Vercel project settings.

Deployment Procedure

Prerequisites

1
Install Vercel CLI
npm i -g vercel or use npx vercel
2
Log in to Vercel
vercel login — authenticates via GitHub, GitLab, or email
3
Check existing projects
vercel list — confirm projects are already created on Vercel

Deploy budolshap (Marketplace)

1
Navigate
cd budolshap-0.1.0
2
Link project
vercel link (first time only) — select existing project or create new
3
Set environment
npm run db:vercel — switches DATABASE_URL to Vercel/Production
4
Preview deploy
vercel — deploys to preview URL (automatically on PR merge if CI/CD is set)
5
Production deploy
npm run deploy:prod or vercel --prod
Scripts: npm run deploy (preview), npm run deploy:prod (production), npm run env:pull (sync env vars)

Deploy budolpay Services (Monorepo)

1
Navigate to root
cd budolpay-0.1.0
2
Link project
vercel link — link to the budolpay monorepo project
3
Set rootDirectory
In Vercel Dashboard → Project Settings → Root Directory: budolpay-0.1.0
4
Set Node.js version
Vercel Dashboard → Project Settings → Node.js Version: 20.x
5
Deploy
vercel --prod — deploys all 7 functions defined in vercel.json
Monorepo caveat: Shared packages (@budolpay/database, @budolpay/audit, etc.) must be resolved correctly. Vercel hoists workspace packages. If you see "Cannot find module" errors, check that @budolpay/* packages have valid "main" entries and vercel.json builds config uses correct source paths.

Deploy budolpay Admin Dashboard

1
Navigate
cd budolpay-0.1.0/apps/admin
2
Link and deploy
vercel link then vercel --prod
3
Verification
Visit the deployment URL — confirm admin login and KYC/audit pages load

Deploy budolID

1
Navigate
cd budolID-0.1.0
2
Deploy
vercel --prod
3
Verify SSO flow
curl https://budolid.vercel.app/.well-known/health — confirm 200 OK

Deploy budolAccounting

1
Navigate
cd budolAccounting-0.1.0
2
Deploy
vercel --prod
⚠ Critical: Database Migrations

Vercel deployments do not run Prisma migrations automatically. After deploying new code that changes the schema:

1
Run npx prisma migrate deploy against your production database
2
Before deploying new code that expects the new schema, apply the migration
3
Use vercel env pull to sync latest production env vars locally first

CI/CD Pipeline

Existing: GitHub Actions (budolpay-0.1.0/.github/workflows/ci-cd.yml)

The existing pipeline builds Docker images and deploys to ECS Fargate. For Vercel, the recommended approach is:

Option A: Vercel Git Integration (Simpler)

1
Connect repo
Vercel Dashboard → Import Git Repository → Select GitHub repo
2
Configure per project
Set root directory, framework, build command per project
3
Auto-deploys
Every push to main deploys to production; PR branches get preview deployments

Option B: Vercel CLI in GitHub Actions (More control)

name: Deploy to Vercel
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npx prisma generate
      - run: npx vercel --prod --token=${{ secrets.VERCEL_TOKEN }}
        env:
          VERCEL_ORG_ID: ${{ secrets.VERCEL_ORG_ID }}
          VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
Required secrets: VERCEL_TOKEN (from Vercel → Settings → Tokens), VERCEL_ORG_ID, VERCEL_PROJECT_ID (from .vercel/project.json after vercel link)

Cron Jobs

Vercel does not have native cron. Use one of these approaches:

1
Vercel Cron Jobs (Pro)
Vercer Pro plan supports crons in vercel.json. Example:
{
  "crons": [
    { "path": "/api/cron/settlement", "schedule": "0 2 * * *" }
  ]
}
2
External cron (Free)
Use cron-job.org, EasyCron, or GitHub Actions schedules to hit your API endpoints
3
Required cron endpoints
• POST /api/cron/settlement — daily merchant settlement (2AM)
• POST /api/cron/cleanup — cleanup expired sessions/tokens (4AM)
• GET /api/health — uptime monitoring (every 5 min)

Rollback Strategy

1
Instant rollback
Vercel Dashboard → Deployments → find previous working deployment → "Promote to Production"
2
CLI rollback
vercel rollback — rolls back to the previous production deployment
3
Git revert
git revert HEAD → push → Vercel auto-deploys the revert
Best practice: Enable "Auto-expose System Labels" in Vercel project settings to track rollbacks in your CI/CD.
